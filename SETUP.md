# 🛠️ Terra 3D — как собрать и выложить игру

Кликер про развитие планет Солнечной системы: 15 эпох Земли, экспедиции на Марс, Юпитер, Венеру и Меркурий
со своими ресурсами, перками и косметикой, кинематографичные переходы эпох, астероиды, звуки и фоновая музыка,
квесты, достижения и сапфиры, промокоды, вход через Google и Яндекс ID, профили, друзья по кодам, альянсы с мощью
(тапы + вложенные кристаллы) и уровнями, чат (общий, альянса, личный), чёрная дыра в измерения CS2 и Майнкрафт,
звуки тапа, обучение новичка, чит-меню администратора и рейтинги — общий, по измерениям и по планетам,
за неделю и за всё время.

Всё собирается автоматически на GitHub: вы загружаете эти файлы один раз, а дальше GitHub сам
собирает **APK** и выкладывает **сервер** на Cloudflare после каждого изменения.

```
web/        игра (одна и та же для APK и для сайта) + config.js с адресом сервера
            js/data.js — планеты, эпохи, постройки, перки, косметика, достижения, цели престижа (баланс);
            js/game.js — движок, графика и интерфейс; js/sound.js — звуки и фоновая музыка (генерируется в браузере)
android/    оболочка APK (Android-приложение, внутри которого запускается игра)
server/     сервер: вход через Google, сохранения, рейтинг (worker.js — для Cloudflare и для своего VPS)
            node/ — запуск на своём сервере, vps/ — автоустановка на VPS (для игроков из России)
            twitch/ — сборка игры для панели под трансляцией на Twitch
telegram/   ежедневные посты в Telegram-канал (тексты, картинки, сценарий публикации)
roblox/     отдельная игра для Roblox (исходники Luau и сборка места .rbxlx)
.github/    сценарии автосборки: «Build APK» и «Deploy server»
```

**Что получится в итоге**

- APK по постоянной ссылке: `https://github.com/ЛОГИН/terra3d/releases/latest/download/terra3d.apk`
- Сайт с игрой: `https://terra-api.ПОДДОМЕН.workers.dev` (на нём же кнопка «📱 Скачать для Android»)
- Общий рейтинг, облачный прогресс и вход через Google — и в APK, и на сайте

На всё уходит около 30–40 минут. Нужны только браузер и бесплатные аккаунты GitHub, Cloudflare и Google.

## Шаг 1. Репозиторий на GitHub

1. Зарегистрируйтесь на [github.com](https://github.com).
2. Справа вверху **+ → New repository**. Имя: `terra3d`. Видимость: **Public** — иначе игроки не смогут скачать APK по ссылке.
   Ключ подписи в репозитории зашифрован, пароль от него хранится только в секретах (шаг 2).
3. Нажмите **Create repository**, затем на странице репозитория ссылку **uploading an existing file**.
4. Распакуйте архив и перетащите в окно **всё содержимое** папки `terra3d`: папки `.github`, `android`, `server`, `web`
   и файлы `README.md`, `.gitignore`. Нажмите **Commit changes**.

> ⚠️ Проверьте, что появилась папка `.github`. На Mac она скрыта: в Finder нажмите **Cmd + Shift + .**, чтобы её увидеть.
> Если папка всё же не загрузилась: **Add file → Create new file**, имя `.github/workflows/android.yml`, вставьте текст
> одноимённого файла из архива, **Commit**. Повторите для `.github/workflows/server.yml`.

## Шаг 2. Пароль ключа подписи и первый APK

1. В репозитории: **Settings → Secrets and variables → Actions → New repository secret**.
2. **Name:** `KEYSTORE_PASSWORD`, **Secret:** пароль, который прислал Claude. **Add secret**.
3. Вкладка **Actions** → слева **Build APK** → **Run workflow**.
4. Через 3–6 минут справа на главной странице репозитория появится **Releases** → `terra3d.apk`.

Пока не сделаны шаги 3–6, это **демо-версия**: играть можно, но без входа и рейтинга. Её уже можно поставить на телефон и посмотреть.

## Шаг 3. Cloudflare (сервер)

1. Зарегистрируйтесь на [dash.cloudflare.com](https://dash.cloudflare.com).
2. В меню слева откройте **Workers & Pages** (раздел Compute). При первом входе Cloudflare попросит выбрать
   **поддомен workers.dev**, например `myname`. Адрес вашего сервера будет `https://terra-api.myname.workers.dev` — запишите его.
3. **Account ID:** на странице Workers & Pages (или на главной странице аккаунта) справа есть **Account ID** → скопируйте.
4. **API-токен:** значок профиля справа вверху → **My Profile → API Tokens → Create Token** →
   шаблон **Edit Cloudflare Workers** → **Use template**. В блоке **Permissions** нажмите **+ Add more** и добавьте
   **Account → D1 → Edit**. **Continue to summary → Create Token** → скопируйте токен (Cloudflare покажет его один раз).

## Шаг 4. Google (вход в игру)

1. Откройте [console.cloud.google.com](https://console.cloud.google.com) и создайте проект **Terra 3D** (выпадающий список проектов вверху → **New project**).
2. Меню **☰ → APIs & Services → OAuth consent screen** (в новой версии раздел называется **Google Auth Platform**) → **Get started**:
   название приложения `Terra 3D`, ваша почта → **Audience: External** → контактная почта → **Create**.
3. Раздел **Audience** → **Publish app** → подтвердите. Статус должен стать **In production**.
   Без этого войти смогут только вручную добавленные тестировщики. Игра запрашивает только идентификатор аккаунта (`openid`),
   поэтому проверка приложения в Google не требуется.
4. Раздел **Clients → Create client**:
   - **Application type:** Web application, **Name:** `Terra`
   - **Authorized redirect URIs → Add URI:** `https://terra-api.ПОДДОМЕН.workers.dev/auth/google/callback`
     (ваш поддомен из шага 3; адрес должен совпадать символ в символ)
   - **Create**
5. Скопируйте **Client ID** и **Client secret**.
   ⚠️ Google показывает секрет только сейчас — сохраните его (можно нажать **Download JSON**).

Отдельный Android-клиент и SHA-1 **не нужны**: в APK вход открывается в браузере телефона и возвращается в игру.

## Шаг 5. Секреты сервера и запуск

Добавьте в **Settings → Secrets and variables → Actions** ещё пять секретов (так же, как в шаге 2):

| Name | Что вставить |
|---|---|
| `CLOUDFLARE_API_TOKEN` | токен из шага 3 |
| `CLOUDFLARE_ACCOUNT_ID` | Account ID из шага 3 |
| `GOOGLE_CLIENT_ID` | Client ID из шага 4 |
| `GOOGLE_CLIENT_SECRET` | Client secret из шага 4 |
| `SESSION_SECRET` | строка, которую прислал Claude (или любые 40+ случайных символов) |

Затем **Actions → Deploy server → Run workflow**. Через 1–2 минуты откройте `https://terra-api.ПОДДОМЕН.workers.dev` —
должна открыться игра с кнопкой **«Войти через Google»**. Попробуйте войти.

## Шаг 6. Адрес сервера в APK

1. Откройте в репозитории файл `web/config.js` → значок ✏️.
2. Замените строку адреса на свою:
   ```js
   API_URL: 'https://terra-api.ПОДДОМЕН.workers.dev',
   ```
3. **Commit changes.** GitHub сам соберёт новый APK (в Releases появится следующая версия) и обновит сайт.

## Шаг 7. Раздайте игру

- **Ссылка на APK:** `https://github.com/ЛОГИН/terra3d/releases/latest/download/terra3d.apk` — всегда ведёт на последнюю версию.
- **Или ссылка на сайт:** `https://terra-api.ПОДДОМЕН.workers.dev` — там можно играть в браузере и скачать APK.

Как установить на телефон: открыть скачанный файл → разрешить установку из этого источника → **Установить**.
Play Защита может предупредить о приложении не из Google Play — это обычное дело для APK: **Подробнее → Всё равно установить**.

Новые версии ставятся поверх старых, прогресс сохраняется: он хранится в облаке и на телефоне.

## Как вносить изменения

Любая правка в `web/` (через ✏️ на GitHub) → через несколько минут новый APK в Releases и обновлённый сайт.
Номер версии растёт сам.

**Игроки узнают об обновлении сами.** Когда выходит новый APK, в игре появляется окно «Вышло обновление»
с кнопкой «Скачать» (и кнопка «Проверить обновление» в настройках ⚙️). Текст «что нового» в этом окне — **первая строка
сообщения коммита** (поле *Commit message* при сохранении на GitHub), так что пишите её для игроков:
например, «Новая планета Сатурн и 5 шапок». Служебные «Update index.html» в окне не показываются.

**Играть можно только в последней версии APK.** Как только в Releases появляется новый APK (сервер узнаёт об этом
в течение ~15 минут), старые версии больше не пускаются в игру: новые показывают окно «Нужно обновление»
с кнопкой «Скачать», а совсем старые (до 1.0.5) выкидывает на экран входа, и вход открывает страницу
«Обновите игру». Сайт не блокируется никогда. Чтобы снова пускать старые версии, добавьте секрет
`FORCE_UPDATE` со значением `0` (Settings → Secrets and variables → Actions) и запустите «Deploy server».

**Где что настраивается.** Баланс престижа — функция `prestigeGoals` и объект `PRESTIGE` в `web/js/data.js`
(`buildCap` — потолок числа построек в цели, рост цели по ресурсу — степень 1.75). Правила друзей и альянсов —
константы в начале раздела «ПРОФИЛИ, ДРУЗЬЯ, АЛЬЯНСЫ» в `server/worker.js`: `FRIENDS_MAX` (100 друзей), `ALLY_MAX`
(30 участников), `TAPS_PER_SEC` (сколько тапов в секунду засчитывается — защита от накрутки), список эмблем.
Альянс может основать только игрок, прошедший последние этапы всех пяти планет Солнечной системы (`PLANET_MAX`, `SOL_IDS`).

**Измерения (CS2 и Майнкрафт).** В `web/js/data.js`: `UNIVERSES` — измерения, их планеты и «пул» перехода
(`need`: `prestige` — престижей в предыдущем измерении всего, `each` — на каждой его планете, `gems` — плата),
`UNIVERSE_BONUS` — +25% дохода за каждое открытое измерение, `NEW_PLANETS` — планеты-карты и планеты-биомы
(названия, ресурсы, этапы, постройки, перки, вид), числа баланса — `PLANET_TEMPLATE` (масштаб: ×1000 в CS2,
×1 000 000 в Майнкрафте). Сервер знает список планет из `UNIVERSE_PLANETS` в `server/worker.js` — при добавлении
планеты правьте оба места.

**Альянсы: кристаллы и уровни.** Мощь альянса = ручные тапы + вложенные 💎 × `ALLY_GEM_POWER` (500). Уровень n —
от n² × `ALLY_LEVEL_STEP` (50 000) мощи, каждый уровень +`ALLY_LEVEL_BONUS` (2%) к доходу участников, максимум
`ALLY_LEVEL_MAX` (20). Константы — в `web/js/data.js` и (те же) в `server/worker.js`.

**Чат.** Раздел «ЧАТ» в `server/worker.js`: длина сообщения (`CHAT_LEN`, 200 символов), защита от спама
(не чаще раза в 1,2 с и 8 сообщений за 30 с), список скрываемых слов `BAD_WORDS`, хранение 30 дней.
Ссылки вырезаются. Админ видит у чужих сообщений кнопки 🗑 (удалить) и 🔇 (закрыть чат игроку на сутки).

**Звуки тапа** — `COSMETICS` с `type: 'sound'` в `data.js`, сами звуки — `tap()` в `web/js/sound.js`.
**Обучение новичка** — массив `TUT` в `web/js/game.js` (шаги, подсветка, награда `TUT_REWARD`); справочник «Как играть» — `HELP` там же.

**Падающие звёзды** — `STAR` (когда и как долго летят) и `STAR_BONUS` (бонусы и их вес) в `data.js`.
**Награда за вход** — `LOGIN_REWARDS` (7 дней) в `data.js`. **Награды недели** — `WEEKLY_PLAYER_REWARDS`
и `WEEKLY_ALLY_REWARDS` (в `data.js` для подсказок в игре и в `server/worker.js` — их выдаёт сервер; правьте оба места).
Сервер отмечает выданную неделю в `player_meta.reward_week`. **Финал** — `checkLegend()` в `game.js`
(титул, корона `hat_legend` и фон `bg-multiverse`).


## Игра без VPN в России: свой сервер (VPS)

С июня 2025 российские провайдеры ограничивают Cloudflare: с его серверов загружаются только первые ~16 КБ,
поэтому вход, рейтинг и сайт на `workers.dev` без VPN не работают. Решение — сервер в России. Код игры тот же,
GitHub сам всё ставит и обновляет.

1. **Купите VPS** у любого российского хостинга (Timeweb Cloud, Selectel, RuVDS, Beget…): **Ubuntu 24.04**,
   1 ядро, 1 ГБ памяти, 10+ ГБ диска — самый дешёвый тариф, ~150–300 ₽ в месяц. Хостинг пришлёт **IP-адрес**
   и **пароль root**. Если в панели хостинга есть файрвол — разрешите порты 22, 80 и 443.
2. **Секреты** (Settings → Secrets and variables → Actions → New repository secret):

   | Секрет | Что вписать |
   |---|---|
   | `VPS_HOST` | IP-адрес сервера, например `185.1.2.3` |
   | `VPS_PASSWORD` | пароль root (или `VPS_SSH_KEY` — закрытый ключ, если хостинг дал доступ по ключу) |
   | `SERVER_DOMAIN` | *необязательно:* свой домен, например `terra3d.ru` (A-запись → IP сервера) |
   | `ACME_EMAIL` | *необязательно:* почта для писем Let's Encrypt о сертификате |

3. **Адрес игры.** Без своего домена — бесплатный `https://<IP через дефисы>.sslip.io`
   (для IP `185.1.2.3` — `https://185-1-2-3.sslip.io`), сертификат HTTPS выпускается сам.
   В [Google Cloud Console](https://console.cloud.google.com/apis/credentials) → ваш OAuth Client →
   **Authorized redirect URIs → Add URI**: `https://185-1-2-3.sslip.io/auth/google/callback` → **Save**.
   (Появится свой домен — добавьте и `https://ваш-домен/auth/google/callback`.)
4. **Actions → Deploy server → Run workflow.** Сценарий:
   - настраивает сервер (Node.js, HTTPS, автозапуск, ежедневные копии базы за 14 дней в `/var/lib/terra/backups`);
   - один раз переносит базу игроков с Cloudflare — весь прогресс и рейтинги сохраняются;
   - переключает Cloudflare в режим переадресации: старый адрес ведёт на новый, вход на сайте переносится сам,
     старые APK получают «Обновите игру»;
   - запускает сборку нового APK, который ходит на ваш сервер и скачивается с него же.

   В итогах сценария (Summary) — адрес игры и проверка, что Google принимает вход.

Дальше всё как раньше: любое изменение в `web/` или `server/` само выкладывается на сервер.
Не удаляйте секрет `VPS_HOST` — без него игра вернулась бы на Cloudflare со старой базой.

## Игра на Twitch: панель под трансляцией

Terra 3D можно встроить в свой канал на Twitch — как **расширение-панель** под видео (318 px шириной, до 500 px высотой).
Зрители играют прямо на странице канала. Входят через аккаунт Twitch, а кто уже играет на телефоне или на сайте,
привязывает тот аккаунт кодом: в игре ⚙️ → «📺 Играть на Twitch» → код → в панели ⚙️ → «🔗 Привязать аккаунт из игры».
После этого прогресс, друзья, альянс и место в топе общие.

Файлы игры для Twitch GitHub собирает сам: в каждом релизе рядом с APK лежит **`terra3d-twitch.zip`**
(сценарий `server/twitch/build.sh`, адрес сервера подставляется автоматически).

**Один раз:**

1. Зайдите на [dev.twitch.tv/console/extensions](https://dev.twitch.tv/console/extensions) своим аккаунтом Twitch
   (Twitch может попросить включить двухфакторную защиту — для кабинета разработчика это обязательно).
2. **Create Extension** → название (например, `Terra 3D`) → тип **Panel** → **Create Extension Version**.
3. Вкладка **Asset Hosting**: Panel Viewer Path — `index.html`, Panel Height — `500`, Config Path — `config.html` → **Save Changes**.
4. Вкладка **Capabilities**: в **Allowlist for URL Fetching Domains** добавьте адрес сервера игры
   (`https://78-24-221-158.sslip.io` — тот же, что открывается в браузере) → **Save Changes**.
5. **Extension Settings** (справа вверху): скопируйте секрет расширения (Extension Secret, строка в base64).
   На GitHub: Settings → Secrets and variables → Actions → **New repository secret** → имя `TWITCH_EXT_SECRET`,
   значение — этот секрет. Затем Actions → **Deploy server** → **Run workflow**. Секрет никому не показывайте.
6. Вкладка **Files** → **Upload Version** → выберите `terra3d-twitch.zip` из последнего релиза на GitHub → **Upload**.
7. **Move To Hosted Test** → **View on Twitch and Install** → **Install** → **Activate** → панель (Panel 1…3).

Для проверки Twitch просит заполнить страницу расширения: логотип 100×100 PNG, обложку (Discovery Image) 300×200 PNG,
скриншоты 1024×768 (4:3), описание, почту автора и ссылки — политика конфиденциальности `https://<адрес сервера>/privacy.html`
и условия использования `https://<адрес сервера>/terms.html` (страницы лежат в `web/`, их правка не выпускает новый APK).

Теперь панель есть на канале, но в режиме теста её видите только вы и аккаунты из **Testing Account Allowlist**
(вкладка Access) — туда можно добавить ники друзей. **Чтобы панель увидели все зрители**, нажмите **Submit for Review**:
Twitch проверяет расширение 8–14 дней, после одобрения — **Release**. Чтобы расширение мог поставить только ваш канал,
впишите в **Streamer Allowlist** (вкладка Access) номер своего аккаунта Twitch (числовой ID, не ник) — до отправки на проверку: после одобрения смена списка требует новой проверки.

**После обновлений игры.** Twitch раздаёт зрителям ту версию, которую вы загрузили, — новые функции в панели появятся,
только когда вы загрузите свежий `terra3d-twitch.zip` как новую версию (Create Version → Files → Upload) и снова
пройдёте проверку. Если обновление меняет формат сохранений, старая панель перестаёт сохранять прогресс
(показывает «на Twitch она появится чуть позже») — после таких обновлений загружайте новую версию сразу.

## Telegram-канал: посты каждый день

Сценарий **Telegram** (`.github/workflows/telegram.yml`) каждый день в 18:07 по Москве публикует пост в канал игры:

| День | Пост |
|---|---|
| Пн | совет по игре |
| Вт | факт о планете (настоящая астрономия + как это в игре) с картинкой |
| Ср | история эпох, достижения, образы |
| Чт | топ альянсов (с сервера игры) |
| Пт | опрос |
| Сб | зал славы — общий топ за всё время |
| Вс | итоги недели — недельный топ перед обнулением |

Если за прошедшие сутки вышла новая версия APK, вместо обычного поста выходит новость об обновлении (текст — первая строка
сообщения коммита). Если для топа пока мало игроков, выходит пост из рубрики «история». Тексты — в `telegram/content.mjs`
(каждая рубрика идёт по кругу, добавлять посты можно прямо на GitHub через ✏️), картинки — в `telegram/img`.

**Подключить (один раз):**

1. Канал в Telegram должен быть **публичным** — с адресом вида `@terra3d_game` (Настройки канала → Тип канала).
2. Напишите [@BotFather](https://t.me/BotFather) → `/newbot` → придумайте имя и username бота (должен заканчиваться на `bot`).
   BotFather пришлёт **токен** вида `123456789:AA…`. Никому его не показывайте.
3. В канале: Управление каналом → **Администраторы** → Добавить администратора → найдите бота по username →
   оставьте право **«Публикация сообщений»** → Сохранить.
4. На GitHub: Settings → Secrets and variables → Actions → **New repository secret**:
   `TELEGRAM_BOT_TOKEN` — токен бота, `TELEGRAM_CHANNEL` — адрес канала с `@` (например, `@terra3d_game`).
5. Проверка: Actions → **Telegram** → Run workflow → выберите вид поста (например, `tip`) → **Run workflow**.
   Через минуту пост появится в канале. Галочка «Только показать пост» покажет текст в отчёте сценария, ничего не публикуя.

Время публикации меняется в строке `cron` в `.github/workflows/telegram.yml` (время UTC: `7 15 * * *` — это 18:07 МСК).
GitHub отключает расписание, если в репозитории 60 дней не было изменений, — тогда в Actions → Telegram появится
кнопка **Enable workflow**.

## Roblox-версия

В папке `roblox/` — отдельная игра Terra 3D для Roblox (свой прогресс и топ внутри Roblox): 15 эпох Земли, 25 построек,
тапы, астероиды, престиж, улучшения Земли и Древо Вечности, сохранения (DataStore), доход за время отсутствия (до 8 ч),
мировой топ и топ сервера. Каждый игрок получает свою 3D-планету в общем космосе — планеты других игроков видно рядом.
Экономика та же, что в основной игре. Проверки без Studio (нужен [Luau](https://github.com/luau-lang/luau)):
`luau roblox/tests/shared_test.luau` — формулы, `python3 roblox/build.py && luau roblox/tests/smoke_test.luau` —
сервер и клиент целиком в «песочнице Roblox» (вход, тапы, покупки, эволюция, астероид, престиж, сохранения).

```
roblox/src/shared/TerraShared.lua          данные Земли и формулы (общие для сервера и клиента)
roblox/src/server/TerraServer.server.lua   сервер: прогресс, покупки, сохранения, астероиды, топ
roblox/src/server/PlanetBuilder.lua        3D-планета по эпохе и постройкам
roblox/src/client/TerraClient.client.lua   камера, тапы, интерфейс
roblox/build.py                            собирает всё в roblox/TerraRoblox.rbxlx
```

**Как выложить:**

1. Установите [Roblox Studio](https://create.roblox.com/) (Windows или Mac) и войдите своим аккаунтом Roblox.
2. Соберите файл: `python3 roblox/build.py` (или возьмите готовый `roblox/TerraRoblox.rbxlx`).
3. Studio → **File → Open from File** → `TerraRoblox.rbxlx`.
4. Проверка: кнопка **Play** (F5). Окно ошибок — **View → Output**.
5. **File → Publish to Roblox** → «Create new experience», название `Terra 3D`.
6. После публикации: **Game Settings → Security → Enable Studio Access to API Services** — тогда и в Studio
   работают сохранения (в опубликованной игре они работают всегда).
7. Чтобы игру видели все: [Creator Dashboard](https://create.roblox.com/dashboard/creations) → игра → заполнить
   опросник о содержимом (Experience Questionnaire) → **Public**. Там же — иконка (512×512) и картинки для страницы.

Обновить игру: поправить файлы в `roblox/src`, снова `python3 roblox/build.py`, открыть новый `.rbxlx` и опубликовать
поверх (**File → Publish to Roblox As** → выбрать существующую игру). Сохранения игроков не теряются.

## Вход с Яндекс ID

Кнопка «Войти с Яндекс ID» появляется на экране входа сама, как только на сервере заданы два секрета.
Аккаунт Яндекса — отдельный от Google (свой прогресс). Почту, имя и телефон игра не получает — только
постоянный номер аккаунта.

1. Откройте [oauth.yandex.ru/client/new](https://oauth.yandex.ru/client/new) (войдите своим Яндекс-аккаунтом).
2. Название — `Terra 3D`, платформа — **Веб-сервисы**.
3. **Redirect URI**: `https://78-24-221-158.sslip.io/auth/yandex/callback` (появится свой домен — добавьте
   и `https://ваш-домен/auth/yandex/callback`).
4. Доступы: достаточно минимального — «Доступ к логину, имени и фамилии, полу» (игра берёт только номер аккаунта).
5. Создайте приложение и скопируйте **ClientID** и **Client secret**.
6. В GitHub: Settings → Secrets and variables → Actions → New repository secret:
   `YANDEX_CLIENT_ID` и `YANDEX_CLIENT_SECRET`.
7. Actions → **Deploy server** → **Run workflow**. Через пару минут кнопка появится и на сайте, и в APK.

## Чит-меню администратора

Нужно, чтобы проверять игру: любые валюты и ресурсы, престижи вверх и вниз, этапы, все планеты и измерения,
все перки и образы, астероид и падающая звезда по кнопке, офлайн-доход, новые задания, обучение, награда за вход
и финал заново, проверка наград недели.

- Включается **секретным кодом** в поле промокода (⚙️ → «Ввести промокод»). Код знает только владелец;
  в репозитории — только его SHA-256 (`ADMIN_CODE_HASH` в `server/worker.js`). Свой код вместо встроенного —
  секрет `ADMIN_CODE` (и «Deploy server»).
- Сервер помечает аккаунт админом навсегда. Меню: ⚙️ → «🛠️ Чит-меню администратора».
- Рейтинг админа сервер принимает без ограничения скорости и может уменьшать (престижи «откручиваются») —
  после проверки верните свой прогресс.
- Снять права: в базе на VPS `UPDATE player_meta SET admin = 0 WHERE sub = '…'`.

## Если у игрока «пропал прогресс»

1. Actions → **Player save** → Run workflow → ник игрока, действие `history`. В итогах запуска — сводка его
   сохранения в каждой ежедневной копии базы (14 дней) и сейчас: престижи по планетам, измерения, кристаллы,
   когда игра и сервер сохранили его в последний раз.
2. Частая причина «пропажи» — игрок прошёл чёрную дыру: первая планета нового измерения начинается с нуля,
   а прошлые планеты и престижи остаются (карта → вкладки измерений; во вкладке «Развитие» видны все престижи).
3. Если прогресс действительно откатился — тот же сценарий с действием `restore` и датой копии (`ГГГГ-ММ-ДД`).
   Перед восстановлением сервер сам делает копию базы в `/var/lib/terra/restore`.

Защита: сервер не принимает сохранение, в котором меньше престижей или пропали открытые планеты/измерения
(так пишет устаревшее устройство — второй телефон, давно открытая вкладка, сбитые часы), и отдаёт облачное —
игра загружает его сама. При входе игра выбирает сохранение по прогрессу, а не по часам устройства.
Админ (чит-меню) это ограничение обходит; после «Сброса» принимается любое сохранение.

## Промокоды

Игрок вводит код в профиле (тап по нику → «🎁 Ввести промокод») или в «Магазине». Код проверяет сервер:
каждый код срабатывает на аккаунте один раз, после 10 неверных кодов подряд — пауза 10 минут.

Встроенные коды (начальный пак, Discord-пак, пак блогера, «первые 100», пак администрации) хранятся в
`server/worker.js` только в виде хэшей — в открытом репозитории их не прочитать. Сами коды знает владелец игры.

**Свои коды** — секрет `PROMO_CODES` (Settings → Secrets and variables → Actions), по одному коду в строке:

```
HALLOWEEN | Пак Хэллоуина | sapphires=5 gems=3 solar=10000 | limit=500 | until=2026-11-10
STREAM | Код со стрима | gems=2 item=bg-nebula
TESTER | Пак тестировщика | all=1000000 | multi
```

- Награды: `gems`, `sapphires`, любой ресурс (`solar`, `water`, `air`, `biomass`, `science`, `regolith`, `ice`,
  `iron`, `oxygen`, `hydrogen`, `energy`, `helium`, `metal`), `all` — каждый ресурс всех открытых планет,
  `item=id` — косметика (например `bg-founder`, `bg-community`, `hat_halo`).
- Необязательно: `limit=N` — всего активаций, `until=ГГГГ-ММ-ДД` — срок, `multi` — можно активировать повторно.
- После изменения секрета запустите «Deploy server» (Actions → Deploy server → Run workflow).
  GitHub не показывает сохранённый секрет — держите копию списка у себя.

> ⚠️ Не меняйте и не удаляйте `android/app/release.keystore` и пароль `KEYSTORE_PASSWORD`.
> Если ключ сменится, новые версии не встанут поверх старых — игрокам придётся удалять игру.
> Сохраните пароль где-нибудь ещё, например в менеджере паролей.

|---|---|
| Build APK: «Нет пароля ключа» | Шаг 2: секрет `KEYSTORE_PASSWORD` |
| Build APK: «Демо-сборка» | Шаг 6: адрес сервера в `web/config.js` |
| Deploy server: «Сервер не выложен: не заданы секреты …» | Шаг 5: добавьте перечисленные секреты и запустите заново |

| Deploy server: ошибка про D1 / `Authentication error` | Шаг 3.4: у токена должны быть права Workers **и** D1 → Edit |
| Google: `Error 400: redirect_uri_mismatch` | Шаг 4.4: адрес `…/auth/google/callback` должен совпадать с вашим поддоменом точно |
| Google: «Доступ заблокирован» / «только для тестировщиков» | Шаг 4.3: **Publish app** |
| В игре: «Сервер ещё не настроен» | Шаг 5: проверьте `GOOGLE_CLIENT_SECRET` и `SESSION_SECRET`, перезапустите Deploy server |
| После входа браузер не возвращает в игру | Нажмите «Вернуться в игру», затем «Открыть другим способом». Проверьте, что стоит последняя версия APK |

| Deploy server: «Не удалось войти на сервер» | Проверьте секреты `VPS_HOST` и `VPS_PASSWORD` (пароль root из письма хостинга) |
| Deploy server: «Сайт не открывается» | В панели хостинга откройте порты 80 и 443; со своим доменом — проверьте A-запись на IP сервера |
| Deploy server: «Домен ещё не настроен» | DNS после покупки домена обновляется до суток — пока игра работает на адресе sslip.io |

## Как устроен вход (для любопытных)

1. Игра создаёт случайный секрет и отправляет на сервер только его хэш, затем открывает `/auth/google/start`.
2. Сервер перенаправляет на Google (`scope=openid`: почту и имя игра не получает).
3. Google возвращает игрока на `/auth/google/callback`. Сервер проверяет ответ Google и выдаёт одноразовый код.
4. Код возвращается в игру: в APK через ссылку `terra3d://auth`, на сайте через `#auth=…` в адресе.
5. Игра меняет код плюс свой секрет на сессию (`/api/auth/exchange`). Перехватить вход по одной ссылке нельзя: без секрета код бесполезен.

При выходе сессия и локальные данные на устройстве стираются, а при следующем входе Google снова спрашивает, каким аккаунтом войти.

## Ручной деплой без GitHub (необязательно)

Нужен Node.js. В папке репозитория:

```bash
CLOUDFLARE_API_TOKEN=... CLOUDFLARE_ACCOUNT_ID=... GOOGLE_CLIENT_ID=... \
GOOGLE_CLIENT_SECRET=... SESSION_SECRET=... bash server/deploy.sh
```

APK можно собрать и в Android Studio: откройте папку `android/`, задайте переменную окружения `KEYSTORE_PASSWORD`
и выполните **Build → Generate APKs** (без пароля APK подпишется отладочным ключом).
